## Architecture and failure behavior

GitHub Pages hosts only the production frontend, bundled same-origin MapLibre worker, Natural Earth geography, license notices and `data/live.json`. The Pages build uses `/storm-chaser/`, excludes authored storm data through a build alias and hides/disables demo mode. Normal local builds keep the accepted demo and loopback reader. Pages makes no browser request to JMA or `/api/live` and needs no API key, tile service or new account. EN/zh-TW footer distinguishes periodic Pages distribution from the local edition and identifies JMA extraction/visualization responsibility.

The Pages collector reuses `Collector`, `Archive`, normalizer, provenance checks, materialization and defensive client snapshot/eligibility contracts. It runs in `.pages-state`, never the owner's `.local/live`. The long feed is reconciled each allowed cycle alongside the short feed. Its observed update and oldest entry must cover the entire 24-hour eligibility window, and it must not be older than two hours or future-dated. This uses JMA's documented several-day/all-arrivals rolling-feed contract; it is not a permanent historical archive or complete basin assertion.

Collector limits remain: 100 new bulletins/cycle, 150-second cycle bound, serial downloads, 8 MB/30-second responses, source URL allowlist, TLS validation, daily byte accounting, quarantine, leases and persisted retry/backoff. Unsupported schema, future timestamps, incomplete ingestion or failed reconciliation prevents publishing. Each output must pass snapshot/provenance/size validation. Source issue/control/retrieval and last collection success stay separate; rebuilding never changes those source times.

A cold run may hit the 100-download cap. It fails without replacing the deployed site, but saves bounded state; another run after the existing five-minute minimum interval can finish reconciliation. **The first deployment may need two manual runs at least five minutes apart.** No guard is bypassed to make bootstrap succeed. A run during persisted backoff cannot mark failed/partial state successful.

State uses a repository-scoped Actions cache, not Pages artifacts: latest raw-backed units and cancellation tombstones, bounded deduplication/cursors, conditional request metadata and recent byte accounting. The Pages-specific archive removes older issuance history and raw feed bodies after each run, retains current provenance and compacts SQLite. This does not change the local-first archive's retention. Cache state must pass integrity and a 16 MiB size limit. Cache restoration is best effort; eviction/loss forces cold reconciliation and can delay publication. Data and raw archive are never added to Git or the public site. Actions caches are accessible to repository workflow users and eligible fork-PR workflows: this state contains **public JMA data only**, no secrets, and is not an appropriate secret store. It is neither a private backup nor a guaranteed durable archive.

Only complete successful cycles publish. The last deployed data remains usable solely within original source validity and age bounds. Failure does not renew timestamps or infer a clear basin. The browser independently marks collection older than 15 minutes stale and excludes source-expired or >24-hour advisories. At the hourly cadence, stale collection labeling between updates is intentional and truthful. Missing/invalid JSON fails closed; retained in-page data also expires without network success. No guarantee of real-time, continuous uptime, scheduled dispatch or warning-service status.
