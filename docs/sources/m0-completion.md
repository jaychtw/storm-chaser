# M0 completion — JMA-first feasibility decision

Reviewed 2026-10-29, Asia/Taipei. **GO for the scoped JMA-first M2 prototype. No production release or multi-agency approval.** Both newly allowed domains returned HTTP 200 in the fresh environment; no network setting was rewritten. CWA remains credential-blocked and JTWC remains origin/CDN-blocked; neither restriction was bypassed or re-probed in this completion pass.

2. [XML PULL use notes](https://xml.kishou.go.jp/considerationforxml.pdf): permitted secondary use, attribution/editing responsibility, prohibition on inventing forecasts or warnings.
3. [XML operating guide](https://xml.kishou.go.jp/jmaxml_guide_20130412.pdf), sections 2.1.3.1–2.1.3.6: information units, validity, corrections/cancellation and source-control time.

## Verified findings and implementation consequences

| Topic | Official finding | M2 behavior / limits |
|---|---|---|
| Polling | High-frequency Atom feeds update every minute and retain **at least the last 10 minutes** of arrivals. Long feeds update hourly and include **several days** of arrivals. XML PULL allows automated retrieval, no registration. | Short feed every **5 minutes**, long-feed bootstrap/hourly reconciliation. This chosen polling interval is a prototype policy, not an official SLA or minimum permitted interval. ETag/Last-Modified are used when provided. |
| Load / failures | JMA says downloads **10 GB/day or more** can cause source-IP blocking, asks clients not to download the same file repeatedly, and warns of maintenance delays/stops. | Deduplicate bulletin URLs/hashes, retain raw files, serialize cycles, cap new downloads to 100/cycle and each file to 8 MB, 30-second request timeout. Failures back off 5/10/20… minutes up to an hour; longer Retry-After is honored. A malformed archived file is quarantined, not downloaded repeatedly. |
| Forecast cadence | Public schedule gives analysis/24-hour products around 50 minutes after 00/03/06/09/12/15/18/21 JST; near-Japan products can be hourly. Five-day forecasts are described at 03/09/15/21 JST + about 50 minutes, with delays possible when multiple systems exist. | Do not treat feed updates as new forecast cycles. Actual report and point timestamps control display. Existing H30 bulletins can carry inherited longer-range horizons offset from the latest analysis (45/69/93/117 hours). The nominal schedule is not a promise of exact delivery. |
| Latest / corrections | Independent unit: Control Title + EditorialOffice + Status + EventID where present. The **latest Control/DateTime** is valid; serial ordering is insufficient. `訂正` corrects the preceding latest information; `取消` cancels the **whole information unit**. | Archive every distinct hash and snapshot. Newer source-control time wins regardless of arrival/serial. Cancellation remains a tombstone: never resurrect an old forecast. Same-control-time conflicting hashes are retained; latest retrieval breaks that unresolved tie deterministically, a local policy requiring review if encountered in real data. |
| Validity | Explicit `Head/ValidDateTime` ends validity at that timestamp. | Honor it. Otherwise source age >8 hours is marked stale and >24 hours excluded from current display. Those age thresholds are conservative local policies, **not official dissipation statements**. Raw history is retained. |
| Lifecycle | Product remarks include typhoon formation, exit from domain, extratropical transition, weakening to TD, reduced formation likelihood, and changes in issue interval. Names/numbers may be empty; terminal reports may omit wind/forecasts. | Preserve native class and remark; explicit `台風消滅…`, reduced-formation-likelihood remarks and extratropical class retire the current typhoon information. Other TD/unclear states remain unknown, not automatically “safe.” Missing names display the native EventID. Tests cover controlled terminal/cancellation forms; not all real lifecycle variants were empirically observed. |
| Archive | Long feed is a rolling **several-day window**, not a permanent historical forecast archive. | Preserve immutable local raw and normalized snapshots. A fresh empty feed or expired archive means **no current usable bulletin**, not “no storms in the basin.” Long outages beyond that window can leave irrecoverable gaps. |
| Coordinates | ISO 6709 signed **latitude then longitude**, slash terminator; the manual distinguishes decimal-degree and degree-minute alternatives by `type`. Decimal positions have 0.1-degree precision. Forecast centers are `ProbabilityCircle/BasePoint`, not uncertainty radii. | Parse only explicit decimal-degree center fields; range-check, then reverse to GeoJSON longitude/latitude. No interpolation or synthetic cone. The inspected product does not explicitly declare a geodetic datum: no datum conversion or sub-grid accuracy is claimed. MapLibre's geographic plotting is an acknowledged display assumption. |
| Winds / pressure | Native fields include knots (`ノット`), m/s, hPa; max sustained wind and max instantaneous wind are separate types. JMA defines typhoon maximum wind as a **10-minute average**. | Preserve every native value/unit/type separately. No incompatible-wind averaging, conversion, consensus, or invented missing values. Averaging convention is documented metadata, not an invented XML field; gust averaging is not asserted. Empty numeric text stays null. |
| Timestamps | Control DateTime is source generation/dispatch time (UTC); ReportDateTime is the official issue time; TargetDateTime is analysis base; per-point DateTime is the actual observation/estimate/forecast valid time. Product examples use JST +09:00; offsets are explicit. | Convert instants to UTC ISO internally; display **Asia/Taipei with UTC+08:00** explicitly. Preserve all source instants and separate retrieval time. Derive lead hours from analysis time, not retrieval, filename or report time. Estimates remain a distinct kind and are not relabeled as observations. |
| Use / attribution | PDL1.0 allows reproduction/transmission/adaptation and commercial use, subject to attribution, editing disclosure, third-party exceptions, specific laws and disclaimers; compatible with CC BY 4.0. JMA XML notes permit redistribution with those limits and reject altered independent forecasts/warnings. | Archive and visualize source values unchanged, with JMA links and edit responsibility. No warning service, invented cone, consensus path or official-chart claim. Graphic-specific embed permissions are not inferred; official-page links remain the fallback. |

## What M0 has and has not established

Feasibility is established for **one documented, attributable, machine-readable JMA forecast source** and a bounded prototype implementation. The [saved specimen](evidence/2026-10-29/jma-vptw61.xml) and actual M2 collection prove fetch/parse/normalization/display for inspected ordinary advisories. Multiple historical cycles were retrieved, not a future changed advisory witnessed after publication. Corrections, malformed data and expiry are verified with controlled mutations of the official specimen; they are explicitly not archived real correction events.

Remaining limitations do not justify claiming production readiness: exact datum, all schema variants, long outages/history gaps, full lifecycle examples, durable scheduling, cross-process archive coordination, monitoring/retention/backups, and a second independent verified agency. See [M2 review](../m2-review.md). No CWA or JTWC capability is promoted to verified live coverage.
