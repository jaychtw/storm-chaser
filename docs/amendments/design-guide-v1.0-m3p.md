# Design Guide amendment v1.0.1 — M3-P scope and uncertain Auto

Approved direction: product owner's [M3-P Final Implementation Authorization](../briefs/m3-p-authorization.md), 2026-10-29 Asia/Taipei. This scoped amendment supplements [Guide v1.0](../Storm_Chaser_Design_Guide_v1.0.md), whose original text remains unchanged. It does not declare v1.0 release acceptance.

- **§§2/3/8, Auto:** retain explainable Taiwan relevance ranking as a v1.0 objective. Until validated evidence and an owner-approved methodology exist, Auto displays a neutral regional overview with no highest-priority storm. This applies even when only one storm is available. Manual choice persists until explicit return to Auto; an ineligible manual choice is explained, never replaced silently. No recency/nearest-center default, derived motion, geographic threshold or confidence score is authorized.
- **§3, cycles/charts:** defer the user-facing historical issuance-cycle browser. Continue to show current bulletin issue/control/analysis/forecast-valid/retrieval/check times distinctly. Clearly labeled official-page links satisfy original-chart access; embedding is not required.
- **§§6/11/12, operations and milestones:** M3-O identifies delivered operational hardening; M3-P is bounded product completion. Preserve the single-host Node/SQLite/systemd design in principle, without activation or procurement. Original M3 multi-agency comparison and relevance objectives remain open. Do not promote this cycle to original M4/RC readiness.
- **§§7/9, data truthfulness:** client and server apply the same explicit validity and existing local >24h display expiry, retaining the >8h stale threshold. Stale-but-eligible can remain visible with source times; expired centers/forecasts are excluded from current views and Auto candidates, including offline/resume. Archived storage is independent and subject to retention, not a source of fresh weather. Expiry never means dissipation or a clear basin.
- **§10, presentation:** display verified reported motion and localized known field/class/unit/condition labels, preserving native data and provenance. Source explanations distinguish integration, collection, local API availability, partial coverage, stale/expired and no usable bulletin. No authoritative translation of source prose is implied.
- **Financial/release boundary:** $0 new expenditure, no account/billing/service enrollment, no unattended source collection, infrastructure activation, public preview, merge into main or deployment. Existing local development and isolated tests are authorized. Completion stops at owner review.

See [ADR 0002](../adr/0002-product-reconciliation-proposed.md) for decision lineage and remaining proposals. AICP 1.1.0 at `cb74fe9497d07370f44a18a09fec124ab99848ec` is adopted prospectively. No game-specific UGDS obligations or standards-repository edits are adopted by this amendment.
